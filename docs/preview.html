最终结论：方案可以继续推进。 作为独立系统，原方案中的 FastAPI、PostgreSQL、Redis、Celery、Docker、Nginx、任务队列、状态轮询、失败重试、统计监控等设计均可保留。V2 重点补强“来源建模、官方字段适配、结果转存、幂等、防重复提交、回调验签、任务状态机、批量任务”。

系统边界

系统负责什么

  • 接收商品图片、卖点、作图参数。
  • 校验图片 URL 可访问性、格式、大小、数量。
  • 创建本地作图任务并进入队列。
  • 调用紫鸟 / LinkFox 开放接口。
  • 轮询或接收回调更新任务状态。
  • 下载第三方结果图并转存到本系统 OSS/CDN。
  • 提供任务查询、下载、导出、Webhook 通知。

系统不负责什么

  • 不负责商品中心、ERP、刊登系统的业务流程。
  • 不直接绑定任何历史 BFF 或内部服务。
  • 不保存第三方账户明文密钥。
  • 不保证 LinkFox 官方任务一定成功，只提供重试和补偿机制。
  • 不把第三方 URL 当作长期稳定资产。
重要约束 LinkFox “商品套图 V3.0”接口字段、鉴权方式、任务查询接口、回调格式，需要在开发前用官方文档和真实账号进行逐项确认。本 V2 文档采用“适配层占位”的方式设计，避免业务模型被第三方字段锁死。

图片来源要求

  • 传给 LinkFox 的图片 URL 必须公网可访问，不应使用本地地址、内网地址、短期临时 URL。
  • 如使用签名 URL，建议有效期不低于 24 小时，避免排队和重试期间失效。
  • 建议系统上传源图到自己的 OSS/CDN 后，再把稳定 URL 提交给 LinkFox。
  • 生成结果必须从 LinkFox URL 下载并转存到本系统，最终对外只暴露 storage_url。

核心组件

API Server

提供任务创建、文件上传、任务查询、批量导入、统计、Webhook 接收等 REST API。

Provider Adapter

封装 LinkFox 鉴权、字段映射、提交任务、查询任务、错误码转换，避免业务层直接依赖第三方字段。

Task Queue

使用 Redis + Celery 管理提交、轮询、下载、转存、通知等异步任务。

Poller

在没有回调或回调丢失时定期查询 LinkFox 任务状态，并推动状态机流转。

Storage Service

负责源图上传、结果图下载、OSS/CDN 转存、文件元数据记录。

Webhook Dispatcher

任务完成或失败后，通知外部业务方，并支持失败重试。

业务流程与状态机

标准任务流程

  1. 调用方提交图片、卖点、模板参数，并带上 Idempotency-Key 或 external_task_id。
  2. API Server 校验参数、图片可访问性、图片数量、格式、大小。
  3. 创建本地任务，状态为 created，随后入队。
  4. Worker 从队列取任务，构造 LinkFox provider_request。
  5. 调用 LinkFox 创建任务，保存 provider_task_id 与 provider_response。
  6. Poller 或 LinkFox 回调更新任务状态。
  7. 任务成功后下载结果图，上传到本系统 OSS/CDN。
  8. 状态变为 completed，触发 Webhook 通知。

推荐状态机

created→ queued→ submitting→ submitted→ generating→ result_downloading→ result_uploaded→ completed
validation_failed submit_failed provider_failed poll_timeout download_failed upload_failed callback_failed cancelled

失败是否重试

失败类型是否重试说明
网络超时 / 连接失败重试指数退避，最多 3 次。
LinkFox 限流重试按 Retry-After 或本地退避策略处理。
5xx 临时错误重试可重试，超过次数进入 dead letter。
参数校验失败不重试需要用户修正参数。
图片不可访问不重试除非重新上传或刷新签名 URL。
内容违规 / 第三方拒绝不重试记录 provider_error_code，提示用户修改素材或文案。
结果图下载失败重试可能是临时网络问题，建议单独 result_transfer queue。

分页查询任务列表，支持状态、来源、批次、创建时间筛选。

POST/api/v1/tasks/{task_id}/cancel

取消本地未提交或正在排队的任务。已提交给 LinkFox 的任务是否可取消，取决于官方接口能力。

POST/api/v1/tasks/{task_id}/retry

对可重试失败任务进行人工重试。参数错误、图片不可访问、内容违规类失败不允许直接重试。

GET/api/v1/tasks/{task_id}/logs

查看任务生命周期日志。

POST/api/v1/webhooks/linkfox

接收 LinkFox 回调。必须保存原始 payload，并进行签名校验、幂等处理和状态更新。

GET/api/v1/stats

返回任务数量、成功率、失败率、平均耗时、队列长度、今日消耗等统计信息。

队列与任务调度

推荐队列划分

队列用途并发建议重试
submit_queue提交 LinkFox 创建任务2-5网络、限流、5xx 可重试
poll_queue查询第三方任务状态3-10短周期重试，避免过度频繁
result_transfer_queue下载结果图并上传 OSS/CDN2-6下载或上传失败可重试
webhook_dispatch_queue通知外部系统2-8指数退避，最多 5 次
dead_letter_queue保存不可自动恢复任务人工处理不自动重试

轮询策略

  • 任务提交后 10 秒开始第一次查询。
  • 生成中每 5-15 秒查询一次，任务多时动态延长间隔。
  • 超过 30 分钟仍无结果，标记为 poll_timeout。
  • 如果官方提供回调，仍保留轮询兜底，避免回调丢失。

幂等策略

唯一约束建议：
- unique(client_id, idempotency_key)
- unique(client_id, source_type, external_task_id)

重复提交处理：
1. 如果已存在 created/queued/submitting/submitted/generating 任务，直接返回原 task_id。
2. 如果已 completed，直接返回结果。
3. 如果已 failed，按参数 allow_retry_on_duplicate 决定是否创建新任务。

图片存储与资产管理

源图处理

  • 上传源图后生成 source 类型资产记录。
  • 校验 MIME、扩展名、文件大小、图片尺寸。
  • 源图 URL 应稳定可访问，并可被 LinkFox 读取。
  • 保留原始文件名、hash、width、height、format。

结果图转存

LinkFox provider_url
  → 后端下载到临时目录或流式读取
  → 校验文件格式与大小
  → 上传 OSS / S3 / MinIO
  → 生成 storage_url
  → 写入 ai_image_assets
  → 对外返回 storage_url
不要长期依赖 provider_url 第三方结果图 URL 可能有有效期、权限变化、清理策略或防盗链限制。系统对外输出应以本系统 storage_url 为准。

安全、鉴权与审计

外部 API 鉴权

  • 使用 Authorization: Bearer <api_key> 或 X-API-Key。
  • 数据库只保存 api_key_hash，不保存明文。
  • 支持 client 级限流、每日额度、并发限制。

LinkFox 密钥管理

  • 密钥通过环境变量或密钥管理服务注入。
  • 日志中禁止输出完整密钥、签名、Authorization Header。
  • 支持多账号配置，为后续额度隔离或多租户预留。

Webhook 验签

推荐自定义对外通知签名：
X-Webhook-Timestamp: 1716448800
X-Webhook-Signature: hmac_sha256(secret, timestamp + "." + raw_body)

接收方校验：
1. timestamp 是否在 5 分钟窗口内。
2. HMAC 签名是否一致。
3. event_id 是否已经处理，防重复消费。

审计日志

  • 记录任务创建、提交、回调、轮询、下载、上传、通知、失败、人工重试。
  • 关键日志带 trace_id、task_id、provider_task_id。
  • 错误日志保存 provider_error_code 和标准 error_code。

实施路线图

Phase 1：最小闭环

  • 完成 LinkFox 官方接口鉴权与创建任务实测。
  • 实现 POST /api/v1/tasks、GET /api/v1/tasks/{id}。

  • 接入 OSS/CDN，完成源图和结果图资产化。
  • 补齐幂等、任务日志、错误码、失败重试、死信队列。
  • 支持 callback_url 和外部 Webhook 通知。
  • 增加管理后台的任务列表、详情、重试、下载。

Phase 3：批量与运营能力

  • 支持 Excel/CSV 批量导入。
  • 支持批量任务统计、导出结果包。
